# ADR 0005 — ثبت‌نام موقت بدون تأیید ایمیل

تاریخ: 2026-10-13 — وضعیت: پذیرفته، موقت با درخواست صریح مالک پروژه.

## دلیل و تصمیم

PostgreSQL و نشست واقعی روی Vercel آماده‌اند، اما مالک هنوز دامنهٔ فرستنده ندارد و درخواست کرده برای آزمون واقعی با گوشی ثبت‌نام و ورود با رمز فعال شوند. متغیر فقط سمت سرور `AUTH_EMAIL_VERIFICATION_REQUIRED=false` این حالت را فعال می‌کند. مقدار پیش‌فرض `true` است؛ مقدار نامعتبر پیکربندی را رد می‌کند. این تصمیم استثنای موقت الزام تأیید ایمیل ADR 0003 است.

حساب تازه همچنان `emailVerified=false` دارد؛ رمز hash می‌شود و نشست واقعی DB ایجاد می‌شود. ارسال تأیید هنگام ثبت‌نام در حالت موقت انجام نمی‌شود. MFA برای ساخت مجموعه و دسترسی مدیریتی، Origin، rate limit، RLS، عضویت تازه و revoke همچنان اعمال می‌شوند. متغیر از درخواست کلاینت پذیرفته نمی‌شود.

## مرز دسترسی

در این حالت مالکیت ایمیل اثبات نشده است و فرد می‌تواند ایمیل شخص دیگری را هنگام ثبت‌نام وارد کند. حساب صرفاً بر شناسهٔ مستقل کاربر به مجموعهٔ خودش دسترسی دارد؛ نباید هیچ داده یا مجوزی با تطبیق این ایمیل به او داده شود. `app.verified_email` برای حساب تأییدنشده تهی است و پذیرش دعوت پیش از خواندن دعوت رد می‌شود. پذیرش دعوت و اتصال حساب مبتنی بر ایمیل از این استثنا استفاده نمی‌کنند. بازیابی رمز و ارسال تأیید بدون سرویس ایمیل در API نیز 503 می‌دهند؛ توکن یا صندوق توسعه عمومی نداریم.

این حالت هویت مدرسه یا صحت ایمیل را تضمین نمی‌کند و برای استفادهٔ نهایی نیازمند فرستنده و تأیید ایمیل است. آزمون‌ها روی DB مستقل با دادهٔ مصنوعی اجرا می‌شوند؛ دیتابیس تولید seed نمی‌شود.

## پایان حالت موقت

پس از آماده‌کردن دامنه و فرستنده، `RESEND_API_KEY` و `AUTH_EMAIL_FROM` تنظیم و تحویل تأیید/بازیابی آزموده شوند. سپس متغیر به `true` تغییر کند و deploy تازه انجام شود. نشست موجود حساب تأییدنشده نیز دیگر به API سازمان دسترسی ندارد؛ حساب‌ها حذف یا خودکار تأیید نمی‌شوند. قبل از اعمال این تغییر، مسیر درخواست ایمیل تأیید برای حساب‌های موقت و پیام راهنمای UI تکمیل شود تا بتوانند مالکیت ایمیل را اثبات کنند. ارسال بازیابی رمز به‌خودی‌خود emailVerified را تغییر نمی‌دهد.

## راستی‌آزمایی

آزمون PostgreSQL: ثبت‌نام بدون ارسال، نشست واقعی، عدم جعل emailVerified، MFA، عدم نشت دعوت با RLS، عدم پذیرش دعوت، بازیابی مسدود، ورود مجدد و بازگشت به حالت سخت‌گیرانه. آزمون مرورگر دسکتاپ/موبایل: ثبت‌نام → MFA → مجموعه/اتاق پایدار → خروج → ورود/MFA، و بازیابی غیرفعال.
