# ADR 0007 — تأیید دومرحله‌ای اختیاری برای حساب

تاریخ: 2026-10-14 — پذیرفته با درخواست مالک برای ساده‌شدن ورود و مدیریت.

## تصمیم جاری

ساخت مجموعه، دسترسی مدیریتی و پذیرش دعوت نقش مدیریتی دیگر به فعال‌سازی MFA نیاز ندارند. نشست معتبر با رمز، ایمیل طبق سیاست فعال، عضویت و نقش تازهٔ همان سازمان کافی‌اند. الزام قبلی MFA برای همهٔ مدیران در ADR 0003 و توضیحات تاریخی ADR 0005 با این تصمیم جایگزین می‌شود.

تأیید دومرحله‌ای ویژگی اختیاری حساب است. اگر فرد آن را فعال کرده باشد، ورود همچنان کد می‌خواهد و نشست قدیمی فاقد proof نباید به مدیریت برسد. فعال‌شدن در نشست دیگر، proof نشست قدیمی را نمی‌سازد. تصمیم الزام از user واقعی نشست تعیین می‌شود؛ هیچ mfa، role یا grant ارسالی مرورگر مبنای مجوز نیست.

صفحهٔ امنیت، وضعیت اختیاری و خاموش‌کردن با رمز صحیح را ارائه می‌کند؛ خاموش‌کردن از endpoint استاندارد Better Auth استفاده می‌کند و نشست تازه می‌گیرد. MFA کاربران دیگر بدون اقدام آن‌ها حذف نمی‌شود، secretها دستکاری نمی‌شوند و proof جعلی ساخته نمی‌شود. خطر سرقت رمز برای حساب تک‌مرحله‌ای بیشتر است؛ این کاهش حفاظت انتخاب صریح مالک برای ساده‌شدن تجربه است. کنترل نقش، RLS، Origin، محدودیت درخواست و revoke باقی‌اند.

الزام MFA برای دسترسی اضطراری پلتفرم مستقل است و با این تصمیم حذف نمی‌شود؛ break-glass هنوز پیاده نشده است. محدودیت دعوت با ایمیل تأییدنشده و بازیابی بدون فرستنده تغییر نمی‌کند.

## آزمون

ثبت‌نام → مجموعه و اتاق → خروج → ورود فقط با رمز، روی موبایل و دسکتاپ. PostgreSQL: مدیر تک‌مرحله‌ای مجاز، فرد خارج سازمان ممنوع، مدیر opt-in با نشست قدیمی رد، خاموش‌کردن با رمز اشتباه رد و رمز صحیح موفق، نشست قبلی لغوشده و ورود بعدی بدون کد. مسیر اختیاری MFA همچنان آزموده می‌شود.
