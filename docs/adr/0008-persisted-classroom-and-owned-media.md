# ADR 0008 — اتاق پایدار و رسانهٔ خودمیزبان، دو پروفایل از یک سورس

تاریخ: 2026-10-16 — پذیرفته‌شده

## مسئله

مالک می‌خواهد محصول واقعی را ابتدا روی ورسل آزمایش کند و همان release را در حالت عادی یا قطع دسترسی بین‌المللی روی سرور خودش اجرا کند. حساب Cloud، CDN فونت، خدمات realtime یا SMTP خارجی نباید پیش‌نیاز اجباری باشند. وب serverless به‌تنهایی جای UDP SFU/TURN نیست.

## تصمیم

وب/API، هویت و همکاری در یک modular monolith می‌مانند. چت و تختهٔ SVG در PostgreSQL با FORCE RLS ذخیره می‌شوند؛ مرورگر snapshot محدود را هر ۸ ثانیه و heartbeat را هر ۲۴ ثانیه می‌گیرد. چت clientId برای جلوگیری از ارسال تکراری دارد. تخته عملیات append و revision برای clear/undo دارد. این نسخه قلم زندهٔ CRDT نیست؛ Yjs و Redis تا اثبات نیاز وارد runtime نشده‌اند.

لینک اتاق یک capability تصادفی، hash‌شده، زمان‌دار، دارای سقف استفاده و قابل لغو است. کاربر باید وارد حساب شود؛ لینک فقط attendee همان اتاق می‌سازد. این روش اثبات مالکیت ایمیل نیست و با دعوت ایمیلی مدیریت مجموعه تفاوت دارد. تعلیق، ban و پایان جلسه با داشتن لینک دور زده نمی‌شوند.

رسانه از LiveKit متن‌باز خودمیزبان و TURN می‌گذرد. Next.js فقط پس از بررسی نشست، عضویت و اتاق توکن حداکثر پنج‌دقیقه‌ای با sessionId امضاشده و منابع انتشار محدود می‌دهد. دادهٔ چت/تخته و roomAdmin در grant مرورگر فعال نیستند. SDK فقط پس از کلیک اتصال بارگذاری می‌شود. روشن‌کردن دستگاه یا اشتراک صفحه همیشه اقدام خود کاربر است.

دروازهٔ signaling مستقل و همیشه‌روشن، JWT و Origin و وضعیت تازهٔ DB را در هر اتصال/reconnect بررسی می‌کند. هر پنج ثانیه نیز دسترسی اتصال‌های برقرار بررسی و در صورت لغو، participant از SFU حذف می‌شود. سیگنالینگ خام SFU و API کنترل تنها loopback/شبکهٔ خصوصی هستند؛ انتشار مستقیم آن‌ها این مدل امنیتی را باطل می‌کند. انقضای مجوز انتشار یک publisher به قطع اتصال و نیاز به join تازه منجر می‌شود. مجوز read-only پشت‌صحنه گسترده نمی‌شود. در اختلال DB دسترسی باز فرض نمی‌شود؛ اجرای حذف رسانه به دسترس‌پذیری API خصوصی SFU وابسته است و قطع آنی/تضمینی ادعا نمی‌شود.

SMTP با TLS معتبر اضافه شد؛ Resend تنها adapter اختیاری تاریخی است. `AUTH_MAIL_TRANSPORT=disabled` حالت آزمایش بدون فرستنده را صریح می‌کند. بازیابی بدون فرستنده همچنان غیرفعال است.

`HAMYAR_DEPLOYMENT_MODE=normal|domestic` یک تنظیم اپراتور است. هر دو از یک image و schema استفاده می‌کنند. domestic اتصال به میزبان‌های تأییدنشده و سرویس‌های Cloud شناخته‌شده را رد می‌کند؛ این allowlist اثبات محل جغرافیایی یا آزمون اینترنت ملی نیست. فایل‌های TLS، imageها، DNS و backup پیش از قطعی باید آماده باشند. انتقال خودکار داده یا failover ساخته نشده است.

## نتیجه و محدودیت

ورسل می‌تواند همکاری واقعی چت/تخته و مدیریت را بدون Cloud رسانه اجرا کند؛ آزمایش رسانهٔ عمومی همچنان به مقصد واقعی SFU/TURN نیاز دارد. آزمون دو مرورگر و SFU محلی انجام می‌شود؛ این آزمون ظرفیت VPS، TURN روی اپراتورهای ایران یا قطعی بین‌المللی را تأیید نمی‌کند. ضبط سروری/Egress و بازپخش خصوصی همچنان مرحلهٔ مستقل بعدی است. ثبت تیکت و برند سازمانی واقعی‌اند؛ پاسخ تیکت بر عهدهٔ مدیر همان سازمان است.

## جایگزین‌ها

ایجاد دو fork جدا باعث اختلاف schema و اصلاحات امنیتی می‌شود. الزام Cloud با خواستهٔ مالک ناسازگار است. P2P mesh برای کلاس چندنفره و uplink ضعیف انتخاب نشد. WebSocket عمومی مستقیم به SFU بدون reauthorization، ban را صرفاً با عمر توکن محدود می‌کند و پذیرفته نیست.
